# 机器学习与深度学习工程工作流

把任务目标、可用输入、选择规则和可验证产物连起来。先读[六类路线](references/routes.md)中匹配的一项；概念带练转[学习教练](../ml-dl-study-coach/SKILL.md)或[深度学习基础](../dl-foundations/SKILL.md)。

本技能提供原创实施方案与检查方法，不附带六个可运行项目、数据集、权重或训练环境，也不预设任何模型成绩。完整合集建议整包安装以保留同级路由；只读取当前任务需要的技能和参考。

## 从任务到最小实验

1. 写清预测对象、观测单位、标签、预测时刻可见字段、成本和主要指标。确认数据、许可、依赖、设备及输出目录是否可用；缺少条件时先给设计，不能宣称已运行。
2. 按组、时间或独立样本假设确定训练/验证/测试划分，冻结最终测试的使用规则。保存划分 ID 或可复现的划分描述；随机种子不能修复错误的切分单位。
3. 建立简单基线。插补、标准化、编码、特征选择、重采样、降维和阈值选择各自标明使用了哪些数据；凡是学习统计量的步骤均置于相应训练折内。测试集不参与模型与阈值选择。
4. 在用户授权的项目目录内，用小样本确认输入输出、单步训练与指标计算，再按预算扩大。使用现有项目环境；需要新增依赖时遵循用户的环境与安装约定，不改动无关环境。
5. 保存版本、配置、划分、预处理、预测与模型工件，并按[评估与恢复](references/verification.md)验证所需范围。文件存在、能导入库或一次高分不能替代端到端证据。
6. 报告实际结果、与基线的差异、错误类型及限制。明确哪些检查执行过，哪些仍是计划；模型运行证据与学习者掌握证据分开。

## 专项检查

- XGBoost 最佳轮、wrapper/native 对齐或重载：读[轮次与模型范围](references/xgboost.md)。
- 检索金标、Hit@k、Recall@k、MRR、BM25 与 ANN 对照：读[检索评价](references/retrieval.md)。
- PyTorch 的推理、固定下一批训练一步与连续数据流恢复：读[恢复层次](references/verification.md)；模式与梯度疑问转[PyTorch 检查点](../dl-foundations/references/pytorch-checks.md)。

需要结构化实验记录时，可将[空记录模板](assets/run-record-template.json)复制到本次项目。模板只有待填字段，不构成任何检查已通过的证据。保存前检查现有同名文件，使用新的运行标识或合并约定，保留可追溯的历史结果。
