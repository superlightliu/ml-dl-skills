# D2L 英文教材阅读与实现导航

先确定正在使用的教材页面、框架分支和代码片段。信息已足够时直接分析；不要把其他框架或历史版本的 API 默认为当前代码。

查 [topic-route.md](references/topic-route.md) 选择问题入口和诊断动作；查 [source-guide.md](references/source-guide.md) 取得官方阅读入口。只读回答当前问题需要的材料。用户没有本地教材时使用官方资源；无法取得原文时明确说明未核对该书表述，不虚构页码、公式编号或已读记录。

## 代码阅读工作流

1. 标记数据、模型、损失、优化器和评价各自的边界。先确定这段代码是教材片段、可运行脚本还是依赖前文定义的 Notebook 单元。
2. 沿一次前向过程记录形状、dtype、设备与广播轴，再检查标签编码、损失的 mean/sum 及掩码分母。
3. 展开真正影响理解的教材辅助函数，核对其定义和调用位置；不能把 d2l 包封装的功能都当作框架内置 API。
4. 检查梯度清零、参数更新、训练与评价模式，以及保存、加载后恢复的状态。反向计算和评价统计要分开说明。
5. 若请求运行，先检查现有环境与资源，设计最小张量或短批次验证。安装、下载数据和完整训练按用户实际请求处理，阅读教材本身不产生这些操作的授权。
6. 对不一致分别排查版本差异、轴约定、辅助函数和概念错误。涉及当前 API 时查所用框架的官方文档；只有核对来源后才称为教材错误。
